## 17. 🔥 GA-style flexible analytics — custom dimensions cho code template + reusable cho mọi template

### 17.1 Vision — GA-style event model

Thay vì hardcode `block_id` field, dùng **`dimensions` JSONB map** (key-value flexible) + **`metrics` JSONB map** (numeric). Mỗi template tự khai báo dimensions phù hợp — không phải migration mỗi lần thêm tracking case.

```json
  "session_id": "string",
```

### 17.2 Schema (proposed)

**Migration:**

```sql
-- Drop hardcoded block_id requirement, add flexible dimensions
ALTER TABLE analytics_events
  ADD COLUMN dimensions JSONB DEFAULT '{}'::jsonb,
  ADD COLUMN metrics JSONB DEFAULT '{}'::jsonb,
  ADD COLUMN event_name VARCHAR(64) NULL,
  ALTER COLUMN block_id DROP NOT NULL;  -- legacy block events vẫn dùng

-- Functional indexes cho common dimension keys (add per-key khi cần,

CREATE INDEX idx_events_section
  ON analytics_events (page_id, ((dimensions->>'section_id')), occurred_at);
CREATE INDEX idx_events_cta
```

JSONB cho phép template tự define dimension keys mà không cần migration. GA chính xác đi theo pattern này.

**Phát hiện 2026-05-31** sau khi §13 fix.

## 13. 🔥 Page bị pin vĩnh viễn ở template_version cũ → public /p/{slug} render version rỗng

**Phát hiện 2026-05-31** — user mở `/p/landing-hero-v1-copy` thấy chỉ "Landing Hero v1 - Copy" + nút "Learn more" (default config) thay vì các block đã save ở editor.

### 13.1 Repro

- Tạo page → BE set `page.template_version_id = template.current_version_id` (vd v1.0.0 với `canvas_blueprint.blocks=[]`)

- **Nhưng**: `page.template_version_id` VẪN = v1.0.0. `template.current_version_id` cũng không đổi.
- User mở `/p/{slug}` → BE render từ release → release snapshot từ `page.template_version_id` (= v1.0.0, blocks rỗng) → user thấy template defaults thay vì content thực.

### 13.2 BE block: 2 path đều không work

```bash
# Path A: update page.template_version_id
curl -X PATCH ... -d '{"template_version_id":"<HEAD_ID>"}' /v1/pages/{id}
# → 200 OK, response page.template_version_id KHÔNG đổi (silently dropped)

# Path B: pass template_version_id ở publish body
curl -X POST ... -d '{"template_version_id":"<HEAD_ID>"}' /v1/pages/{id}/publish
# → 201, release tạo nhưng snapshot vẫn rỗng (BE ignore body, dùng
#   page.template_version_id)

# Swagger schema:
#   UpdatePageRequest: {name, slug, description, type_metadata,
#                       freeze_products, thumbnail_asset_id}
#                      → KHÔNG có template_version_id
#   PublishPageRequest: {version_label}
#                      → KHÔNG có template_version_id
```

### 13.3 Impact

- Mọi page bị STUCK ở version đã có khi create. User không bao giờ publish được content mới.
- Save Version feature ở editor thành no-op cho public render — chỉ phục vụ editor reload (FE workaround HEAD load, commit 9d13b38).
- `pages.publish` toggle ở `/admin/landing-pages` kebab cũng không giúp — chỉ tạo release mới từ cùng version rỗng.

### 13.4 Fix BE (chọn 1)

**Option A (preferred):** Cho phép `template_version_id` ở `UpdatePageRequest`. Validate version thuộc cùng template_id. Cho admin tự chọn version để pin.

**Option B:** Auto-bump `page.template_version_id` to `template.current_version_id` (hoặc HEAD) ngay khi createVersion với cờ "promote=true", hoặc auto-promote luôn nếu page đang publish.

**Option C:** Cho phép `template_version_id` ở `PublishPageRequest.body` → publish snapshot từ version chỉ định thay vì page.template_version_id. FE chủ động chọn version mỗi lần publish.

Option C linh hoạt nhất + ít breaking (chỉ thêm optional field).

### 13.5 FE plan (interim, không cần đợi BE)

- Banner cảnh báo ở editor (đỏ): "Public /p/{slug} đang render version cũ (vN.M.K). BE chưa cho FE đổi version. Cần BE ship fix §13."

## 19. 🔥 Hard delete (purge) endpoint cho pages

**Requested 2026-05-31** — Sales/marketing dọn rác landing pages thử nghiệm. Hiện chỉ có soft archive (`DELETE /v1/pages/:id` → status='archived'). Bị tích luỹ archived pages vô hạn — DB phình + admin list rối.

### Current behavior
- `DELETE /v1/pages/:id` → `h.Archive()` → set `status='archived'`, releases deactivate. Reversible qua `POST /v1/pages/:id/restore`.
- Không có endpoint xoá vĩnh viễn.

### Need
Endpoint xoá vĩnh viễn page khỏi DB. Yêu cầu BE:

- **Endpoint:** `DELETE /v1/pages/:id?force=true` (preferred — same path, query param) HOẶC `DELETE /v1/pages/:id/purge` (separate route).
- **Guard:** chỉ accept khi `page.status='archived'`. Page đang live/draft → 409 reject.
- **Cascade:** xoá luôn `page_versions` rows tham chiếu, `analytics_events` cho page_id đó (hoặc anonymize → set page_id=NULL), domain bindings.
- **Audit log:** record actor + timestamp (compliance).
- **Idempotent:** double-call → 204 lần 2 (page gone).

### FE status
- FE đã stub `rexerApi.pages.purge(id)` gọi `DELETE /v1/pages/:id?force=true`.
- UI gate behind env flag `NEXT_PUBLIC_ENABLE_HARD_DELETE_PAGES`. Flag = `true` → bulk action bar hiện nút "Xoá vĩnh viễn" (chỉ khi tất cả selected đều `status='archived'`). Modal type-to-confirm gõ "XOA" trước khi gọi API.
- Khi BE ship → set flag, smoke test, sync naming nếu BE chọn `/purge` route khác.

### Related
- §1, §13 page lifecycle. Reference: `internal/server/http/handler/page_canonical.go:207` (current `Archive()`).
