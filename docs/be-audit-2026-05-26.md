## 12. 🔥 PATCH `/pages/:id` silently drops `slug` → public `/p/{slug}` 404

**Update 2026-05-31** — phát hiện khi user thử share link sau Publish.

### 12.1 Symptom

User publish page → set slug "landing-hero-v1-copy" qua PublishDialog → mở `/p/landing-hero-v1-copy` → 404 "Landing not found".

### 12.2 Root cause (probe)

```bash
# 1. Page hiện slug = ""
curl -H "Cookie: $CK" /v1/pages/a0ec43d8-... | jq .page.slug
# → ""

# 2. Try set slug
curl -X PATCH -H "Cookie: $CK" -H "Content-Type: application/json" \
  -d '{"slug": "landing-hero-v1-copy"}' \
  /v1/pages/a0ec43d8-...
# → 200 OK + response page object with slug: "" (UNCHANGED)

# 3. Verify
curl -H "Cookie: $CK" /v1/pages/a0ec43d8-... | jq .page.slug
# → "" (still empty)
```

Swagger `UpdatePageRequest` schema:
```
fields: description, freeze_products, name, thumbnail_asset_id, type_metadata
```
→ KHÔNG có `slug`. BE drops extra fields silently → response 200 misleading.

### 12.3 Impact

- Tất cả page tạo qua `CreatePageRequest` mà thiếu `slug` (vd "Tạo từ template" dialog không có slug input) → **vĩnh viễn không thể có public friendly URL**. Phải dùng legacy `/p/{template_id}/{share_token}`.
- FE PublishDialog (commit 1adaf78) đã ship slug-input form → user click "Lưu slug" → toast "Đã đặt slug" → reload → slug vẫn rỗng → confused. Đã rollback ở commit này, thay bằng notice rõ "BE chưa cho đổi slug".

### 12.4 Fix BE

Option A (minimal): thêm `slug *string` vào `UpdatePageRequest` struct + handler validate uniqueness/format giống CreatePage. Cho phép admin đổi slug bất cứ lúc nào.

Option B (alternative): nếu slug immutable là cố ý — trả 400 `ERR_BAD_REQUEST` khi PATCH có `slug`, đừng drop silent.

### 12.5 FE plan

- **Bỏ slug-setter UI** ở PublishDialog — chỉ hiện notice "Page chưa có slug. BE hiện chưa cho đổi sau khi tạo".
- Thêm `slug` input vào dialog "Tạo landing từ template" (CreatePageRequest đã accept slug) để user đặt ngay khi tạo.
- Public `/p/{slug}` URL chỉ làm việc cho page tạo có slug từ đầu.
