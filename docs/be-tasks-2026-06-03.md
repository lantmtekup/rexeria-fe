## 2. 🟠 P1 — Publish flow: version pin & public render

FE flow (đã làm đúng phía FE): **Sửa → autosave draft → Save Version (`createVersion`)
→ Xuất bản (`pages.publish` với `template_version_id`)**. FE vừa fix để Publish luôn
commit draft→version mới trước (tránh publish bản cũ).

### 2a. `current_version_id` không bump sau `createVersion`
- **Triệu chứng:** `POST /templates/{id}/versions` tạo version mới nhưng
  `template.current_version_id` vẫn trỏ version cũ.
- **Hệ quả:** bất kỳ chỗ nào render/đọc theo `current_version_id` sẽ thấy bản cũ.
  FE đang workaround (editor load HEAD = max `version_no`; publish gửi
  `template_version_id` để repoint page).
- **BE cần làm:** sau `createVersion`, set `template.current_version_id = <new version>`
  (hoặc xác nhận field này deprecated và mọi render dùng `page.template_version_id`).

### 2b. Xác nhận `/public/pages/{slug}` trả `canvas_blueprint.blocks`
- **Bối cảnh:** audit §15 ghi BE `/p/{slug}` renderer chỉ output HTML placeholder
  (page name + nút "Learn more" tĩnh). FE canonical `/p/[id]/page.tsx` đã **tự render
  blocks** từ field `canvas_blueprint` trong response JSON (component `PublicBlockRender`),
  chỉ fallback HTML khi blocks rỗng.
- **BE cần làm / xác nhận:** `GET /v1/public/pages/{slug}` của page đã publish phải trả
  field **`canvas_blueprint`** (snapshot từ `page_releases.canvas_blueprint_snapshot`)
  có `blocks[]` đầy đủ. Nếu BE chỉ render HTML server-side mà không trả JSON blocks →
  FE không render được → trang trống.
- **FE chưa verify được** (xem mục 1: không có page published nào để test sau khi data mất).
  Cần BE seed lại để test cùng nhau.
